风控模型最怕的不是波动大，而是「波动大的方式」悄悄换了——均值回来了、波动率翻倍了、相关性塌缩了，用上月参数管下月风险等于蒙眼开车。检测制度切换（regime switch）的工业标准是 CUSUM：累积偏离，越界就报警。它便宜、好用，但有一个要命的歧义：**它分不清「制度变了」和「制度内噪声大了」**——高波动制度里一根普通大阳线就能把它再次触发，误报连天。

贝叶斯在线变点检测（BOCD，Adams & MacKay 2007）给出另一种思路：不累积证据，而是对「当前这一段活了多久」（run length）维护一个完整后验。新数据来了，先问「它像不像是新段的第一天」，再更新。本文用 numpy 从零实现（Normal-Gamma 共轭 + 精确递推 + Viterbi 回溯），在 500 日三段制度的合成收益上，和 CUSUM 正面对比。

结论先放这：

**① 在线检测抓「显眼」的变点又准又安静。** 平静期（σ=0.8%）切到崩盘期（σ=2.0%）的第 152 天报警——延迟 2 日、误报 0，峰值概率 0.888；平静期 150 天的误报基线只有 0.0003（最大 0.010），阈值 0.30 之下毫无絮语。
**② 但它对「噪声带内的漂移」结构性失明。** 崩盘期切回恢复期（σ 2.0%→1.0%）时，在线信号全程静默——恢复期的日常观测在崩盘期的宽预测分布里毫不惊喜，单日概率永远爬不过阈值。这是 BOCD 的原理性盲区，不是调参能解决的。
**③ Viterbi 离线分割两个都抓。** 靠 200 天恢复期的累积证据，MAP 分割在 152 和 302 两天报告变点，延迟均 2 日、漏报误报皆零。
**④ CUSUM delay 相当但吵得多。** 两个真变点都抓到（153 日、299 日），但在崩盘制度内误报 4 次（166/176/199/251）——高波动里的普通大阳线被当成了变点。制度尺度跟踪（run > 20 天）MAP 后验 MAE 0.146，均值 MAE 0.119，够风控用。

## 一、合成数据：三段制度，两个变脸时刻

500 个交易日，三段制度：calm（μ=0.03%、σ=0.8%，第 0–149 天）、crash（μ=−0.10%、σ=2.0%，第 150–299 天）、recovery（μ=0.06%、σ=1.0%，第 300–499 天）。真实变点在第 150 和 300 天。注意第二个变点的设计是故意的：波动率**下降**、均值只挪了 0.16pp——崩盘期的宽分布（σ=2.0%）把恢复期的观测全罩住了，没有任何单日数据会「显得突兀」。这是对检测器最诚实的考法。

## 二、BOCD：对「这段活了多久」维护后验

模型假设：观测在段内 i.i.d.，段与段之间参数不同；每期以恒定危险率 H 开启新段（H=1/100，先验期望段长 100 日）。共轭先验取 Normal-Gamma（μ 和精度 τ 联合先验），后验预测是 Student-t——重尾，这很重要：它让「新段第一个观测」永远有个体面的解释概率，不会被旧段的窄分布一棒子打死。

递推的核心是对 run length r 的精确后验（约定 r = 当前段已观测天数，含当天）：

```
R_t(1)   = H · p(x_t | 先验) · Σ_r R_{t-1}(r)        # 当天开启新段
R_t(r+1) = R_{t-1}(r) · (1−H) · p(x_t | 段r的统计量)   # 老段延续
```

每个 run 只需携带充分统计量（n、均值、M2、κ、a、b），Student-t 预测密度闭式可算。Viterbi 版把求和换成取 max 并记回溯指针，最后从终点回溯出最可能的整条分割路径。完整实现：

```python
def pred_logp(xv, m, kap, a, b):
    """Normal-Gamma 后验预测（Student-t）对数密度"""
    nu = 2 * a
    scale = math.sqrt(b * (kap + 1) / (a * kap))
    z = (xv - m) / scale
    return (math.lgamma((nu + 1) / 2) - math.lgamma(nu / 2)
            - 0.5 * math.log(nu * math.pi) - math.log(scale)
            - (nu + 1) / 2 * math.log(1 + z * z / nu))

for t in range(T):
    xv = x[t]
    logp = {r: pred_logp(xv, mean_run[r], kap_run[r], a_run[r], b_run[r])
            for r in range(1, t + 2)}
    lp_prior = pred_logp(xv, M0, K0, A0, B0)           # 新段首点用先验预测
    # 滤波：变点分支 + 延续分支
    new_log_R[1] = log(H) + lp_prior + logsumexp(log_R[1:t + 2])
    new_log_R[2:t + 3] = log_R[1:t + 2] + log(1 - H) + logp[1:t + 2]
    # Viterbi：同结构，求和换 max，记 back[t][r]
    ...
    # 每 run 用共轭公式更新 (n, mean, M2, kappa, a, b)
```

p(x_t | 先验) 这一项是本文约定的关键：变点分支用**先验预测**解释新段首点（而不是旧段的预测），所以 P(r_t=1) 会在真变点当天直接尖峰——观测信号干净，不需要等一天。先验本身取弱信息（κ₀=0.01、a₀=b₀=0.01），先验预测的尺度约为 10 个百分点的量级，对日收益（以 % 计）来说足够弥散，不会把新段首点一棒子打死；但也没有宽到浪费证据。计算量是 O(T²)（每期对每个 run 更新一次统计量），500 日在 numpy 里几秒钟跑完，实时挂盘没有工程压力。

## 四、在线检测：抓得到显眼跳变，抓不到带内漂移

在线信号取 P(r_t = 1)（「当天开启新段」的概率），阈值 0.30，局部峰 5 日合并。

![在线变点概率 P(r_t=1)](/images/bayesian-structural-breakpoint/cp_probability.png)

第 152 天尖峰 0.888，延迟真变点 2 日——崩盘头两天的极端观测（σ 从 0.8% 跳到 2.0%）在 calm 段的窄预测里是天文数字级别的意外，后验毫不犹豫倒向「新段」。而平静期 150 天，P(r=1) 均值 0.0003、最大 0.010，离阈值十万八千里，零误报。但第 300 天附近，曲线全程贴地——恢复期日复一日的温和观测，在崩盘段 σ=2.0% 的宽预测下毫无惊喜，单日概率永远爬不上去。算一笔账就明白：崩盘段跑了 150 天，后验预测尺度已经学到 2.0% 左右，而恢复期的日波动只有 1.0%——一个 μ=0.06%、σ=1.0% 的样本，落在「μ=−0.10%、σ=2.0%」的分布里，z 值也就 0.08，密度几乎打平。**宽分布罩住窄分布的样本，是在线检测的原理性盲区**：波动率崩塌式变脸，只能等证据累积。

## 五、离线 Viterbi 与 CUSUM：一个更准，一个更吵

![检测质量对比](/images/bayesian-structural-breakpoint/detection_quality.png)

Viterbi 回溯给出全局 MAP 分割：152 和 302 两天，延迟均 2 日，漏报误报皆零——它不看单日惊喜，看 200 天恢复期的累积似然，「这些数据整体不像崩盘段生成的」足以压过先验对长段的偏好。CUSUM（稳健标准化、双侧、k=0.5/h=5.0）在第 153 天首次越阈（延迟 3 日），299 天也报了（提前 1 日，运气），但 166/176/199/251 四天在崩盘制度内误报——高波动里 +3% 的普通阳线就把统计量推过阈值。这正是开头说的歧义：CUSUM 没有「段」的概念，不会把段内波动学进尺度。

![制度跟踪：MAP run 后验均值与波动](/images/bayesian-structural-breakpoint/regime_tracking.png)

副产品是制度跟踪：MAP run 的后验预测尺度在 calm 段贴住 0.8%、崩盘段抬到 2.0% 附近（run > 20 天时尺度 MAE 0.146、均值 MAE 0.119），后验均值同样在三段间正确切换。变点刚过的几天尺度被先验顶高（新段还没攒够观测），这是「新段不确定性」的诚实体现——风控上反而该欢迎：刚变脸时模型承认自己不确定，比 CUSUM 越一次阈就全量切换保守得多。

## 六、怎么用，以及别怎么用

三个方法论要点。**其一，在线和离线是两种生意**：在线 P(r=1) 便宜（O(T²) 递推、每期一个数）、适合挂盘告警，但只对「惊喜型」变点敏感；离线 Viterbi 准（吃全样本）、适合收盘后重估制度参数，但要接受 2 日上下的确认延迟。**其二，危险率 H 是主要调参**：H=1/100 意味着先验认为段均 100 日；放到日频行情上，若你认为制度以季为单位就该设 H≈1/60，设成 1/1000 则告警会迟钝到失去意义——先验段长就是你对「市场多久变一次脸」的先验。**其三，别把检测器直接当交易信号**：2 日延迟 + 新段不确定性期，等它确认了，行情已经走完一半；它的正确位置是风控系统的上游——波动率目标、风险预算、保证金假设的切换触发，而不是方向性下注。

局限也说清楚：段内 i.i.d. 假设对日收益的波动率聚集是明知故犯（crash 段内的 GARCH 式聚集会让后验尺度抖动）；H 恒定意味着不会自我适应；本文只有两个变点的小样本考场，真实市场里漏报误报的权衡会比 0 和 4 难看。另一个隐性代价是阈值 0.30 这个魔数：它在本数据上工作得很好，换一片资产、换一个抽样频率就要重新校——本质上是在「延迟」和「误报」之间选一个 operating point，没有免费的默认值。把这些算进去，「对 run length 维护完整后验」这个框架本身，仍然是把「市场变脸」从艺术变成可计算事件的最干净的方式之一。
