## 一、结论先行

一个没有预测能力的策略，每天看一次回测结果，只要 P 值低于 0.05 就宣布发现 alpha——这个流程在三年里会把它误判成有效策略的概率推到 **41.5%**。这不是直觉夸张，而是 12000 条零均值日收益路径的实测结果。名义上的「5% 显著性」在反复偷看之下已经完全失真。

e-value 序贯检验给出另一条路：把「支持策略有效的证据」构造成一个非负 supermartingale。只要零假设成立，它的期望不会随时间增加；Ville 不等式保证「过程中任何时候越过 1/α」的概率不超过 α，哪怕你天天盯、甚至根据越界时间决定何时停止。本文用阈值 20 的混合 e-process 在同样的 756 天零策略模拟里得到 **2.3%** 的虚警率，稳稳守在 5% 以下。

代价也必须讲清楚。年化真实夏普 1.27 时，固定 756 天终点的一次性 z 检验检出率是 **71.3%**，e-process 是 **48.2%**。它换取的是「随时可以停、随时有效」的自由度，而不是更高的功效。如果你坚持每天看结果，那 71.3% 的终点检验优势根本拿不到——因为你不会等到终点。

## 二、反复偷看为什么会把假阳性放大

固定样本量的教科书检验只在预先约定的那一天有效。设日收益服从 N(μ, σ²)，检验 H0: μ=0 对 H1: μ>0，在 n 天终点用 z=Ś_n/(σ√n) 与 1.645 比较，零假设下的误报率确实是 5%。但如果你每天算一次 z，只要任何一天越界就停止并宣布有效，你实际上在做一个**多重检验**：756 天里有 756 个机会碰运气，而且这些统计量高度相关，Bonferroni 又过于保守。

![零策略与真实策略下的 e-process 路径](/images/e-value-sequential-testing/fig1_eprocess_paths.png)

上图左侧是零策略下的六条路径，右侧是日均收益 0.0012（年化夏普约 1.90）的六条路径。红色虚线是 log(20)≈3.00 的停止线。零策略的轨迹偶尔上蹿，但整体被一条缓慢下行的包络压住；真实策略的轨迹则多数稳步穿越停止线。这个「不会无限向上漂移」的性质，正是 e-process 与累积收益或 t 统计量的本质区别。

虚警率随监控天数增长的结果更直观：第 63 天时，反复 z 检验已经误报 **28.1%**，e-process 仅 **0.008%**；第 252 天分别是 **35.8%** 与 **0.67%**；到第 756 天，前者 **41.5%**，后者 **2.3%**。固定终点的一次性 z 检验在同一批零策略数据上是 **5.0%**，说明模拟本身没有偏离理论。

## 三、把证据写成 supermartingale

固定 λ>0 时，Wald 型 e-value 定义为

```
E_t(λ) = exp( λ·Ś_t − 0.5·λ²·σ²·t ),   Ś_t = r_1 + ... + r_t
```

在 H0: μ=0 下，E[exp(λr_i)]=exp(λ²σ²/2)，于是 E[E_t|F_{t-1}]=E_{t-1}：它是一个非负鞅，期望恒为 1。Markov 不等式立即给出 P(E_t≥1/α)≤α；Ville 不等式把它加强到整个过程：P(∃t: E_t≥1/α)≤α。这就是「随时有效」的全部数学来源，不需要预先约定样本量，也不需要修正停止规则。

问题在于 μ 未知，λ 选小了没功效、选大了在错误方向上迅速衰减。标准做法是对 λ 做混合：

```
E_t = ∫ E_t(λ) dπ(λ)
```

混合后的过程仍是非负 supermartingale。本文取 λ∈[0,20] 上 41 个网格点，权重为正态 N(8,5) 的离散化密度，对应「我认为日均 alpha 在 8bp 附近，但允许很大不确定性」的先验。算法全部用 numpy 向量化，`logsumexp` 负责数值稳定。

```python
import numpy as np
from scipy.special import logsumexp
from scipy.stats import norm

sig = 0.01                      # 已知日波动 1%
T, N = 756, 12000
lams = np.linspace(0.0, 20.0, 41)
lw = np.log(norm.pdf(lams, loc=8.0, scale=5.0))
lw -= logsumexp(lw)             # 归一化的对数权重

def e_and_z(S):
    # S: (n_paths, T) 累计收益
    t = np.arange(1, T + 1)
    exp = (S[:, :, None] * lams[None, None, :]
           - 0.5 * lams[None, None, :]**2 * sig**2 * t[None, :, None])
    logE = logsumexp(exp + lw[None, None, :], axis=2)
    z = S / (sig * np.sqrt(t[None, :]))
    return logE, z
```

注意 E_t 不是 P 值，也不能反过来当作「策略为真的概率」。它只是一个在零假设下不会系统性上涨的财富过程：涨到 20 意味着「如果真没 alpha，出现这么强证据的概率不超过 5%」。

## 四、功效曲线：诚实的取舍

在 756 天终点、真实年化夏普从 0 扫到 2.54 的实验中，三条曲线差别明显。固定终点 z 检验在所有非零夏普处都最灵敏，但你必须承诺不看中途数据；e-process 在夏普 0.63 / 1.27 / 1.90 / 2.54 时的检出率分别是 **14.2% / 48.2% / 83.0% / 97.9%**。反复偷看的 z 检验数字更好看（弱信号下 66.1%），可它在零假设下已经有 41.5% 的虚警率——那多出来的「功效」纯粹是噪声。

![不同真实夏普下的检出概率](/images/e-value-sequential-testing/fig3_power.png)

停止时间进一步说明问题。真实日均收益 0.0012 时，e-process 在越界路径上的中位停止时间是 **336 天**；朴素的每日 z 检验只要 **53 天**就宣布胜利，但其中混入了大量在零假设下同样会早早越界的路径。所谓「快速发现 alpha」，很多时候只是「快速自欺」。

## 五、把它接进真实回测流程

序贯检验不是一行 P 值替换，而是一套研究纪律。我的落地顺序是：先在策略立项文档里写下零假设、预期效应量、波动率估计窗口和 λ 先验，再开始跑回测；随后用训练期单独估 σ，把它冻结；最后才在验证期逐日累加 e-process。这个顺序很枯燥，但它是把「随时有效」从数学定理变成工程保证的唯一办法。

记录层面要保留三样东西：每天的 E_t、当天的策略累计收益、以及是否触发了停止规则。只保存最终结果会让事后复盘无法区分「策略真有 alpha」与「路径运气好」。如果 E_t 在验证期越界，不要立刻上线——最好再留一段完全独立的样本外区间做确认，因为越界本身就是从同一批数据里选出来的事件。

另一个常见疑问是：能不能把它用在多个策略的自动监控上？可以，但必须预先分配错误预算。比如同时监控 20 个子策略，把每个的阈值提到 1/(20×0.05)=100，保证「族级别」误报率仍不超过 5%。阈值提高会让单点策略更难越界，这是控制多重检验必须付的钱，而不是方法失效。最后，止损与止盈规则一旦介入，停止时间就不再由 E_t 单独决定；此时 e-process 给出的只是证据上限，不能再当作严格的决策规则。

## 六、四个必须记住的实操边界

**第一，σ 必须先验给定或用训练期估计。** 上面公式假设波动率已知。若用同一批数据边的收益估 σ，零假设下的鞅性质不再严格成立。稳健做法是留一段无策略历史专门估波动，或改用Student-t 似然与相应 e-variable。

**第二，before-you-look 的先验要写进代码。** λ 网格和权重必须在看结果之前定死。看到策略先涨了再回来调 λ 中心，等于把数据挖掘藏进了「序贯检验」的外衣里。更稳妥的做法是覆盖一个很宽的 λ 区间，或者报告不同先验下结论是否稳健。

**第三，一次检验只管一个策略。** 如果你同时跑 200 个策略参数，每个都跑一条 e-process，再挑最先越界的那个，多重检验问题原封不动地回来了。正确的做法是把预算按策略数分配阈值（例如各自用 1/(200α)），或者对策略族做分层检验。

**第四，随时有效不等于随意解读。** 「今天 E=18，快到 20 了」不能当成快要显著的证据；停止规则一旦被人为干预，保证就失效。实盘里更值得关注的是 e-value 的增长速率是否跟得上交易成本、容量衰减与样本外验证。

## 七、小结

量化研究里最贵的错误，往往不是模型不够复杂，而是把噪声反复 interrogation 成信号。e-value 序贯检验用一条非负 supermartingale 把「看多少次都有效」变成可证明的性质：本实验中 756 天天天监控的虚警率从 41.5% 压到 2.3%。它不会让弱策略变强——夏普 1.27 时功效从终点检验的 71.3% 降到 48.2%——但它让每一次「发现」都经得起推敲。

如果你的回测流程里存在「每天看一眼 P 值，显著就上线」这一步，最便宜的修复不是换个模型，而是把那一步换成一条 e-process。
