## 一、结论先行

「A 导致 B 吗？」在量化里不是哲学问题——动量到底驱动了收益，还是两者都被第三个变量（流动性）驱动？方向搞反，策略就建在流沙上。

最常用的工具是 Granger 因果：把 Y 对 Y 和 X 的滞后项回归，看 X 的系数是否显著。但它有一个致命前提——**因果必须能写成线性投影**。当系统是混沌的、耦合是非线性的，这个前提就塌了。

收敛交叉映射（Convergent Cross Mapping，CCM，Sugihara et al. 2012）走的是完全不同的路子。它来自 Takens 嵌入定理：如果 X 真的驱动了 Y，那么 X 的历史信息就被「刻录」在 Y 的时间序列里。于是可以在 Y 的影子流形上找邻近点，反过来重构 X。**关键判据有两个：方向不对称 + 随库长收敛。** 真正被驱动的方向，重构技能 rho 会随着样本库变长单调上升并饱和；反方向则趴着不动。

真值已知的单向耦合实验里，两个序列的相关系数只有 0.074（线性视角下几乎无关），但 CCM 的正向 rho 从库长 60 时的 0.372 一路爬到 1400 时的 0.906，反向始终在 0.01 附近。差异相当于约 37 个代理数据标准差——方向识别得干干净净。

## 二、为什么 Granger 会在混沌系统里失明

Granger 检验的零假设是「X 的滞后项对预测 Y 没有增量信息」。它把「因果」定义成了「线性可预测性」。这在两个世界里会出问题。

第一，耦合是非线性的。如果 Y 的演化依赖 X 的高阶或振荡函数，线性投影抓不到，检验就会漏判。第二，也是更隐蔽的，当系统高度同步时，X 和 Y 的线性投影彼此都装不下对方——因为它们的关系是确定性的、而非统计线性的。本文第四节会看到一个反直觉的结果：近乎完美的镜像序列，Granger 两个方向的 p 值分别是 0.179 和 0.187，全都「无因果」，而相关系数是 -1.000。它把确定性的共演化误读成了「谁也预测不了谁」。

CCM 换了一个问题：不问「X 能不能预测 Y」，而问「Y 的状态里有没有 X 的痕迹」。前者是统计预测，后者是动力学的状态重构——这是根本性的视角差异。

## 三、CCM 怎么算

第一步是状态空间重构。对时间序列 Y，用延迟坐标搭一个 E 维影子流形：

```
M_Y(t) = [Y(t), Y(t-τ), Y(t-2τ), ..., Y(t-(E-1)τ)]
```

Takens 定理保证，只要 E 足够大，这个流形和真实系统微分同胚——原本藏在多维状态空间里的动力学，被完整保留在单变量序列的延迟坐标里。

第二步是交叉映射。要检验「X 是否驱动 Y」，就在 Y 的流形上重构 X：对每个目标时刻 t，找 M_Y(t) 的 E+1 个最近邻，用指数距离权重对这些邻居时刻的 X 值做加权平均，得到 X 的估计。如果 X 真的驱动 Y，Y 的邻近状态就对应着 X 的邻近状态，估计值会贴近真值，相关性 rho 高。

第三步是收敛检验。把可用于查找的历史库长度 L 从 60 逐档加到 1400，每档随机抽多个库取平均。因果方向的 rho 会随着 L 上升并饱和——因为库越大，越可能在流形上找到真正贴近目标状态的邻居。非因果方向的 rho 不随 L 变化。这叫「收敛性」，是 CCM 区别于普通相关性的核心证据。

下面是最小可运行实现：

```python
import numpy as np
from scipy.spatial import cKDTree

def manifold(v, E=3, tau=1):
    n = len(v)
    idx = np.arange((E-1)*tau, n)
    return np.column_stack([v[idx-k*tau] for k in range(E)]), idx

def cross_map(x, y, E=3, lib_sizes=None, pred_L=400, W=10, nrep=16):
    """从 y 的影子流形重构 x：检验 y <- x 的驱动（即 x 是否驱动 y）"""
    if lib_sizes is None:
        lib_sizes = [60, 120, 250, 500, 900, 1400]
    My, iy = manifold(y, E)
    pred_idx = np.arange(len(iy)-pred_L, len(iy))
    cand = np.arange(W, len(iy)-pred_L-W)
    out = []
    for L in lib_sizes:
        rs = []
        for _ in range(nrep):
            lib = rng.choice(cand, size=min(L, len(cand)), replace=False)
            tree = cKDTree(My[lib])
            xhat = np.empty(len(pred_idx))
            for j, p in enumerate(pred_idx):
                d, ni = tree.query(My[p], k=E+1)
                keep = np.abs(iy[lib[ni]] - iy[p]) > W   # Theiler 窗，排除时间近邻
                nb, dd = ni[keep], d[keep]
                w = np.exp(-dd/max(dd.min(), 1e-12))
                xhat[j] = np.sum(w*x[iy[lib[nb]]]) / np.sum(w)
            rs.append(np.corrcoef(x[iy[pred_idx]], xhat)[0,1])
        out.append(np.mean(rs))
    return lib_sizes, np.array(out)
```

注意 Theiler 窗口 W——它排除了时间上紧挨着的点，否则「邻居」只是因为时间接近而相似，会把自相关伪装成因果。这是新手最常踩的坑。

## 四、四组真值已知实验

我用两个耦合的逻辑斯蒂映射生成数据（r=3.7，500 点烧入，4000 点留样），四个场景逐一验。

**场景 A：X 单向驱动 Y。** Y 的演化里乘了一个 `1+0.15(X-0.5)` 的因子，X 不受 Y 影响。结果：相关系数只有 0.074，线性视角下几乎无关；但正向 rho（从 Y 重构 X）从库长 60 的 0.372 单调升到 1400 的 0.906，反向（从 X 重构 Y）始终在 0.012 附近。把 Y 随机打乱做代理数据，8 次平均 rho 只有 -0.031、标准差 0.025——真实的 0.906 高出约 37 个标准差。这就是收敛性和方向性同时成立的教科书案例。

![图2：交叉映射技能随库长收敛——因果方向爬升饱和，反方向趴着不动](/images/convergent-cross-mapping/fig2_convergence.png)

**场景 B：双向耦合。** 两个序列互相驱动，两个方向的 rho 分别是 0.816 和 0.835，都高且接近——CCM 正确报告了「互为因果」。

**场景 C：共同驱动。** Z 是混沌源，X 和 Y 都是 Z 的不同函数，彼此没有直接因果。Granger 两个方向都给出极小 p 值（1.3e-77 和 0.0），CCM 两个方向的 rho 也高达 0.788 和 1.000。**这是 CCM 的软肋**：共同驱动会让两个序列的流形都嵌入了 Z 的信息，互相都能重构。此时必须配合条件CCM或外部知识排混淆，不能单看 CCM 下结论。

**场景 D：镜像同步。** Y ≈ -X 加极小噪声。相关系数 -1.000，但 Granger 两个方向 p=0.179/0.187 全部「无因果」——确定性关系骗过了线性检验。CCM 两个方向 rho 都是 0.98，能告诉你「强耦合」，但同样无法定方向。诚实地说：完美同步的系统，从观测序列里分辨不出谁驱动谁。

## 五、嵌入维度怎么选

CCM 对嵌入维度 E 敏感。在场景 A 上扫 E=2 到 6：E=3 时 rho 最高（0.877），E=4 是 0.843、E=5 是 0.783、E=6 掉到 0.720，而 E=2 只有 0.826。呈先升后降的倒 U 形——维度太低装不下系统动力学，太高则邻居变得稀疏、距离失真，最近邻的「邻近」意义被稀释。实操里可以对 E 做小规模扫描，取 rho 饱和前的最小值；tau 通常取 1 或互信息第一个极小值。这些参数没有万能默认值，报告结果时要一并说明，否则别人无法复现你的 rho。

还有一个容易被忽略的参数是预测集与库的重叠。本文把库限制在预测区间之前、并用 Theiler 窗口 W=10 隔离，就是为了防止时间上紧邻的点既是「邻居」又是「待预测点」——那等于用答案查答案，rho 会虚高到接近 1 却毫无意义。凡是 CCM 结果漂亮得离谱的，第一反应就该是检查时间隔离有没有做对。

## 六、和传递熵、Granger 的分工

三种因果工具其实在回答三个不同的问题。Granger 问「加进 X 的滞后项能不能提高线性预测精度」，快、稳、可给出 p 值，但只认线性。传递熵（Transfer Entropy）问「知道 X 的过去能把 Y 的不确定性减少多少」，能抓非线性、不依赖模型形式，但需要分箱或密度估计，样本效率低、对参数敏感。CCM 问「Y 的状态里是否嵌着 X 的动力学」，专为确定性混沌系统而生，靠收敛性和方向性做判断，但不给出传统意义上的 p 值，且怕共同驱动。

在量化实践中，我的经验是：线性关系先用 Granger 快速筛一遍；怀疑有非线性或状态依赖时，再用 CCM 和传递熵交叉验证。三者一致时结论最硬；分歧本身往往揭示系统里有同步、共同驱动或非线性耦合结构，值得单独研究——分歧不是噪音，是信号。

## 七、给量化研究的落地建议

第一，别把 CCM 当因果的「最终判决」。它在单向非线性耦合上最可靠；遇到共同驱动和强同步会失灵，必须结合领域知识和其他方法交叉验证。第二，收敛曲线比单点 rho 更有说服力——如果你的 rho 不随库长变化，无论多高都要怀疑是自相关或样本泄漏造成的假象。第三，务必做代理检验（打乱时间顺序）建立显著性基线，否则无从判断 0.3 的 rho 是高是低。第四，把 CCM 和 Granger 一起跑：两者都指向同一方向时信心大增；分歧时恰恰说明系统里有非线性或同步结构值得深挖。

在因子研究里，一个典型用法是检验「资金流是否驱动了价格发现」这类非线性领先滞后关系——这正是线性 Granger 容易失手的地方。CCM 提供的是第二条独立证据链，而不是替代品。理解它的边界，比记住它的公式更重要。
