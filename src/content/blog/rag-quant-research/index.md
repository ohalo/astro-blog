研究员的知识管理是个反讽：你读过几百篇研报、记了几十个因子想法，真到要构建一个新策略时，却只能凭记忆想起"好像有篇讲动量的说过什么"。知识在硬盘里，但**不在你的推理链路里**。检索增强生成（Retrieval-Augmented Generation, RAG，Lewis et al. 2020）正是解这个病的：把每篇文档编码成一个向量，查询时先"拽出"最相关的几段，再基于这些证据做判断——让结论**有据可查**，而不是凭幻觉。

量化研究是 RAG 的天然主场：研报、公告、因子说明书、回测日志，全是文本；而我们要的恰恰是"从历史研究里检索出对当前市场有用的因子证据"。本文不堆框架，用 numpy 从零实现一个最小可用 RAG，并跑通两条链路：**检索精度**和**检索增强的因子排序回测**。

结论先放这里（全部来自现场的 numpy 计算）：

**① 朴素 TF-IDF 检索已经够用。** 在 150 篇覆盖 5 个因子主题的合成研报上，top-5 检索精度 **1.000**、top-10 精度 **1.000**——不训模型、不调向量库，纯词频统计就能把"相关研报"捞出来。

**② 检索到的共识能变成 alpha。** 把"检索 top-20 研报对各因子的报告收益取共识"作为排序信号，做多共识最高的 2 个因子，回测 Sharpe **1.465**，明显高于等权买入基准的 1.423，逼近知道真实边缘的上限 1.580。

**③ embedding 真的把主题分开了。** PCA 把 196 维 TF-IDF 向量压到 2 维，五个因子主题几乎不重叠——说明"语义相近的研报向量也相近"这件事，在词频层面就成立。

## 一、RAG 在量化研究里的位置

一个典型的量化 RAG 流水线分四步：

1. **入库（index）**：把研报 PDF → 文本 → 切chunk → embedding → 向量库。
2. **检索（retrieve）**：给定查询（比如"高波动环境下动量因子会不会崩"），返回最相似的 k 个 chunk。
3. **增强（augment）**：把检索到的证据拼进提示词/上下文。
4. **生成/决策（generate）**：LLM 写综述，或直接用检索到的数字做因子排序。

本文聚焦第 2、4 步里"可计算"的部分：用 TF-IDF 当 embedding（轻量、可解释、零依赖），用"检索共识"当决策信号。真实生产里把 TF-IDF 换成句向量模型（BGE、E5 等）即可，框架完全不变。

## 二、从零实现 TF-IDF 检索（numpy）

中文没有空格，所以先做最简单有效的切分：ASCII 词整体保留，中文按**二元字组（bigram）**切。这样"动量"和"动量崩溃"会共享"动量"这个 token，检索就能命中。

```python
import re, numpy as np

def tokenize(text):
    text = text.lower()
    toks = re.findall(r"[a-z0-9]+", text)          # 英文/数字词
    cjk = re.findall(r"[一-鿿]", text)               # 中文按二元字组
    for i in range(len(cjk) - 1):
        toks.append(cjk[i] + cjk[i + 1])
    return toks

def build_tfidf(docs):
    toks_list = [tokenize(d) for d in docs]
    vocab = sorted({t for toks in toks_list for t in toks})
    v2i = {v: i for i, v in enumerate(vocab)}
    N = len(docs)
    df = np.zeros(len(vocab))
    for toks in toks_list:
        for t in set(toks):
            df[v2i[t]] += 1
    idf = np.log((N + 1) / (df + 1)) + 1.0          # 平滑 IDF
    D = np.zeros((N, len(vocab)))
    for i, toks in enumerate(toks_list):
        L = len(toks)
        for t in toks:
            D[i, v2i[t]] += 1.0 / L
    D *= idf
    D /= np.linalg.norm(D, axis=1, keepdims=True)   # L2 归一化
    return D, v2i, idf

def retrieve(D, v2i, idf, query, k=20):
    q = np.zeros(D.shape[1])
    for t in tokenize(query):
        if t in v2i:
            q[v2i[t]] += 1.0
    q = q * idf; q /= (np.linalg.norm(q) + 1e-9)
    sim = D @ q
    return np.argsort(-sim)[:k], sim[np.argsort(-sim)[:k]]
```

`D @ q` 就是余弦相似度（因为两边都 L2 归一化了）。查询一句话，返回最相关的 k 篇研报——十行核心代码，没有 torch、没有向量库。

## 四、现场结果二：检索增强的因子排序回测

光会检索不够，得证明"检索到的东西能改善决策"。我们设计一个极简但可证伪的实验：

- 五个因子各有真实日度边缘 `mu`（动量最高、波动率最低且为负），并模拟了 756 天的因子收益序列。
- 研报库每篇笔记都"报告"了它所属因子的一个带噪边缘估计。
- 给定一条策略简报，检索 top-20 篇研报，对每个因子取"被检索到的笔记报告收益"的**共识**作为该因子的得分；做多得分最高的 2 个因子，构成组合。

![检索增强因子排序的组合净值](/images/rag-quant-research/fig3_equity_curve.png)

图 3 是三种配置的净值曲线：**RAG 因子排序**（绿，Sharpe **1.465**）、**等权买入基准**（红，Sharpe 1.423）、**已知真实边缘的上限**（灰虚线，Sharpe 1.580）。RAG 排序跑赢等权——因为它借检索到的"研报共识"压低了低边缘因子（波动率）的权重、抬高了高边缘因子（动量、情绪）的权重，相当于用文本里蕴藏的历史证据做了一次粗糙但有效的因子择时。

需要泼的冷水：这个"共识"本质是**用历史笔记收益估计因子边缘**，和直接用因子历史均值没本质区别；它的真正价值在于——当研报里还混着"宏观评论、情绪调查、波动率预警"等非结构化信息时，检索能把它们和因子边缘对齐，让一个不会读 PDF 的回测引擎也能用上这些证据。真实的 RAG 因子库，检索到的应当是"因子定义 + 适用环境 + 历史 IC"，而不是一句收益数字。

## 五、在真实研究里怎么落地

1. **chunk 比整篇更重要。** 一篇 40 页研报塞一个向量，会淹没在平均里。按"小节/表格/因子说明"切 chunk，检索命中率立刻上来。
2. **元数据一起检索。** 把"因子名、适用市场状态、回测区间、IC"作为结构化字段，和向量做混合检索（hybrid search），比纯向量稳。
3. **给检索结果留出处。** 每一条因子结论都链回原文段落，审计、复盘、合规都靠它——这也是 RAG 相对"让 LLM 直接编"的最大优势。
4. **定期重索引。** 因子有效性会漂移，研报库要随新研究增量更新，不然检索到的是三年前的"真理"。

## 六、泼一点冷水

本文用 TF-IDF 是为了零依赖、可复现；它在小库、主题词明确时够用，但语义检索（同义、上下位）是它做不到的——"趋势"和"动量"在 TF-IDF 眼里是两个不相交的词。生产环境请换句向量模型。另外，检索精度高 ≠ 决策质量高：如果研报库本身充满过拟合的"伪发现"，RAG 只会更快地把你带沟里。**垃圾进，检索出来还是垃圾**，这一步省不了因子层面的严谨检验。
