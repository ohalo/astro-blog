风险价值（VaR）是量化风控的地基，可它有个几乎所有教科书都轻描淡写的软肋——**它假设市场波动是平稳的**。现实里波动率会跳：平静期日波动 0.8%，危机一来直接翻到 4%。用过去 250 天数据算的 VaR，在变点发生后长达数月里都偏窄，等它终于"反应过来"，最危险的时期已经过去了。

本文把**贝叶斯在线变点检测（Bayesian Online Changepoint Detection，BOCD）**接到 VaR 上。核心不是又造一个更复杂的波动率模型，而是让估计器自己判断"最近的规律是不是失效了"，一旦怀疑变点，就迅速降低对历史数据的信任、把风险估计放宽。我们在一份**已知变点真值**的数据上做这件事，这样覆盖率、违约次数、定位精度都能被严格检验。

## 一、为什么滚动窗口会在变点上栽跟头

先说清对手。250 日滚动历史 VaR 的做法是：取过去 250 天收益的 1% 分位数作为明天的 99% VaR。它有两个硬伤。

第一是**滞后**。假设第 1000 天波动率从 0.7% 跳到 4%，滚动窗口要等旧的平静数据全部滚出去，得花整整 250 天。这段时间内它的 VaR 严重低估，违约（实际损失超过 VaR）会扎堆出现。

第二是**权重粗暴**。窗口内第 1 天和第 250 天的数据被同等对待，可显然最近的信息更相关。加权方法（如 EWMA）缓解了这点，但仍预设了一个固定的衰减速度，无法根据市场状态自适应。

BOCD 的思路完全不同：它不假设一个固定窗口或固定衰减率，而是维护一个关于**运行长度（run length）**的概率分布。运行长度 $r_t$ 指的是"当前这一段已经持续了多少天"——变点发生后它归零，之后逐日增长。知道 $r_t$，就知道该用多少历史数据估波动。

这里的关键转变是从"点估计"到"分布"。传统方法给运行长度一个确定值（比如就用 250 天），BOCD 则保留 $P(r_t=0),P(r_t=1),\ldots$ 的完整分布：可能今天有 30% 概率刚发生变点、50% 概率处于第 5 天、20% 概率在市场已经平静了很久。这个不确定性本身就是信息——它让我们在"不知道是否变盘"的时候自动采取更稳健的折中估计，而不是武断地押注某一种状态。所有后续决策（VaR、仓位、止损）都用这个分布做加权，这才是贝叶斯方法相对于点估计的真正优势。

## 二、运行长度后验：贝叶斯在线变点检测

BOCD 由 Adams 和 MacKay 在 2007 年提出。它在线递推 $P(r_t\mid x_{1:t})$——给定到今天为止的所有观测，当前运行长度的分布。

设危险率 $H$ 为任意一天发生变点的先验概率（本文取 $1/100$，即平均 100 天一变）。递推分两步。

**预测（增长 + 重置）**：今天运行长度为 $r$ 的概率，来自昨天长度 $r-1$ 延续下来（概率 $1-H$），或者今天发生变点被重置到 0：

$$
P(r_t=r)=\begin{cases}
\sum_{r'}P(r_{t-1}=r')\cdot H & r=0\\
P(r_{t-1}=r-1)\cdot(1-H) & r\ge 1
\end{cases}
$$

**更新（用今天的观测加权）**：用每段数据的边际预测似然 $p(x_t\mid r_t=r)$ 乘上去再归一化。对零均值、方差未知的高斯，配逆伽马先验，边际预测分布是 Student-t，尾部比正态厚，正好抗住偶发的极端值。

下面是核心递推，为效率做了向量化（对全部运行长度一次性算 t 分布似然）：

```python
import numpy as np
from scipy import stats

a0, b0 = 1.0, 0.0001      # 方差的逆伽马弱先验
hazard = 1.0 / 100.0       # 变点危险率
MAX_RUN = 150

def bocd_run(x):
    p = np.zeros(MAX_RUN + 1); p[0] = 1.0     # P(r_t)
    s2 = np.zeros(MAX_RUN + 1)                 # 各运行长度对应的段内平方和
    cp_prob = np.zeros(len(x)); mean_r = np.zeros(len(x))
    rgrid = np.arange(MAX_RUN + 1)
    an_base = a0 + rgrid / 2.0
    nu = 2 * an_base
    for t, xt in enumerate(x):
        growth = np.zeros(MAX_RUN + 1)
        growth[1:] = p[:-1] * (1 - hazard)     # 延续: r-1 -> r
        growth[0] = p.sum() * hazard            # 变点: 重置到 r=0
        s2_new = np.zeros(MAX_RUN + 1)
        s2_new[1:] = s2[:-1] + xt**2
        s2_new[0] = xt**2
        bn = b0 + s2_new / 2.0
        scale = np.sqrt(bn / an_base * (1 + 1.0/(rgrid+1)))
        loglike = stats.t.logpdf(xt, df=nu, loc=0.0, scale=scale)
        growth *= np.exp(loglike - loglike.max())   # 减最大值防下溢
        p = growth / growth.sum()
        s2 = s2_new
        cp_prob[t] = p[0]                  # 今天发生变点的后验概率
        mean_r[t] = np.dot(rgrid, p)       # 运行长度期望
    return cp_prob, mean_r
```

有个工程细节值得强调：先验尺度 $b_0$ 必须和数据方差同量级。我最初设成 0.02，比实际方差（约 $4\times10^{-4}$）大了 50 倍，结果预测分布宽得离谱，VaR 过度保守到 1350 天只有 1 次违约——覆盖率 0.07%，比目标 1% 还低一个数量级。把 $b_0$ 校准到 $10^{-4}$ 后结果才合理。这是贝叶斯方法最常见的坑：先验不是摆设，尺度错了整套推断都跟着跑偏。

## 三、从运行长度到动态 VaR

拿到运行长度后验，怎么变成 VaR？我用期望运行长度 $E[r_t]$ 决定有效历史窗口，用该窗口的平方和估计方差，再取 Student-t 分布的 1% 分位数：

```python
def var_from_runlen(t, mean_r_t, rets):
    r = max(1, mean_r_t)
    an = a0 + r / 2.0
    w = int(min(r, 120))                       # 有效样本数随运行长度伸缩
    s2 = np.sum(rets[max(0, t-w):t+1]**2)
    bn = b0 + s2 / 2.0
    nu = 2 * an
    scale = np.sqrt(bn / an * (1 + 1.0/(r+1)))
    return stats.t.ppf(0.01, df=nu, loc=0, scale=scale) * 100
```

直觉很清楚：平静期运行长度大，$E[r_t]$ 可能到 80、100，用到上百天数据，方差估得稳、VaR 窄；一旦变点发生，$E[r_t]$ 迅速掉到个位数，估计只看最近几天，一旦观测到大波动，VaR 立刻放宽。下图红线（BOCD）清楚地跟着四个真变点（竖虚线）上下跳动，而蓝线（250 日滚动）明显慢半拍。

注意这里还有一层精妙之处：Student-t 预测分布的自由度 $\nu=2a_0+r$ 也随运行长度变化。样本少时 $\nu$ 小、尾部更厚，t 分布的 1% 分位数比正态更极端——这正好补偿了"数据少、估计不确定"带来的风险。换句话说，BOCD 在变点后不仅因为观测到大波动而放宽 VaR，还因为"我对新段了解不够"而主动再加一层安全垫。这种把估计不确定性直接编码进风险度量的做法，是固定窗口分位数方法给不了的。

## 四、回测：谁真的守住了 99%

评价 VaR 不能只看"违约少"，违约太少说明估计过宽、浪费资本。标准做法是 **Kupiec 无条件覆盖检验**：在 99% 置信下，违约率应统计上等于 1%，用似然比统计量 $LR_{uc}$ 检验。

数据分 5 段共 1600 天：日波动 0.8%（400 天）→2.2%（300 天）→0.7%（350 天）→**4.0% 危机**（250 天）→0.9%（300 天），真变点在 400/700/1050/1300 天。剔除前 250 天预热，剩 1350 天：

| 方法 | 违约次数 | 覆盖率 | Kupiec p 值 | 结论 |
|------|---------|--------|-------------|------|
| BOCD 动态 | 12 | 0.89% | 0.676 | 通过 |
| 250 日滚动 | 33 | 2.44% | 0.000 | 拒绝 |
| 全样本固定 | 16 | 1.19% | 0.506 | 通过（但有前视偏差） |

BOCD 覆盖率 0.89%，Kupiec 无法拒绝它等于 1% 的原假设，说明估计既不保守也不激进。滚动窗口覆盖率 2.44%，是目标的两倍多，被 Kupiec 断然拒绝——它就是"后知后觉"的量化证据。全样本法看着也通过了，但那是用整段数据（含未来）算出的单一 VaR，属于**前视偏差的作弊**，实盘中根本拿不到，这里只作参照基准。

![三种方法的违约率对比](/images/bayesian-change-point-var/bocd-coverage.png)

真正拉开差距的是分段违约。在日波动 4% 的危机段，BOCD 只有 2 次违约，滚动窗口 14 次，全样本 16 次——因为滚动窗口和全样本都还没把这么高的波动纳入估计，而 BOCD 在变点后约两周内就把 VaR 从 -6% 量级抬到 -10% 以上。下面这张图把每次变点前后各 60 天的 VaR 对齐叠在一起，可以更直观地看到这个"抬升速度"：第一个和第三个变点（波动率上跳）后 VaR 分别放大到 2.71 倍和 4.98 倍，而波动率下跳的变点后 VaR 反而收窄。

## 五、变点定位与局限

BOCD 不只给 VaR，还顺带输出变点概率 $P(r_t=0)$。在真值 ±60 天窗口内，它定位到了 4 个变点中的 3 个：第 400 天检测到 402（误差 2 天），第 1050 天检测到 1050（误差 0 天），第 1300 天检测到 1338（误差 38 天）。平均绝对误差 13.3 天。定位不是它的主业，精度只能算够用——变点概率的峰值有时偏低（最高仅 0.30），噪声段的假峰也不少。

![运行长度后验均值](/images/bayesian-change-point-var/bocd-runlength.png)

必须说清三个局限。其一，本文数据由分段常数波动的高斯过程生成，恰好是 BOCD 的"舒适区"；真实波动率是连续漂移的，变点模型会频繁误报。其二，危险率 $H$ 和先验超参需要人为设定，虽然结果对它们不算特别敏感，但绝非免调参。其三，VaR 本身只看分位数、不关心尾部之外的损失有多深，加密货币或极端跳空场景下应配合 Expected Shortfall 一起用。

尽管如此，这篇文章想传达的核心很简单：**风险估计的"记忆长度"不该是固定的**。当市场结构可能突变时，让数据通过贝叶斯后验告诉你该信多少历史，比拍脑袋定一个 250 天窗口要可靠得多。完整代码、数值结果与四张图随文提供，可逐位复现。
