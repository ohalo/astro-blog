做风控的人都有过这种直觉：**真正吃掉基金的，不是 everyday 的那点波动，而是一年里最惨的那几周**。可经典的均值-方差优化盯的是方差——它把涨和跌对称地平方相加，于是一只「平时很乖、偶尔崩盘」的资产，和一个「每天小幅上上下下」的资产，只要二阶矩相同，在方差眼里毫无区别。

这就是方差最大的盲区：**它不区分尾巴**。

条件风险价值（CVaR，也叫 Expected Shortfall）专门补这块。给定置信水平 α（比如 95%），CVaR_α 是「最差的 (1−α) 那部分情景的平均损失」。它只盯着左尾，所以凡是能让最坏 5% 变轻的操作，都会被它奖励。本文的目标很直接：**把 CVaR 直接写进优化器的目标函数**，而不是事后再去检查 VaR。

下面的所有数字，都来自一个可复现的 numpy + CVXPY 实验，情景里埋了一个真实的「崩盘因子」。

## 一、为什么 CVaR 能写成线性约束

VaR 不可加、不次可加，塞不进凸优化器；但 CVaR 可以。Rockafellar 和 Uryasev 在 2000 年给出了一组漂亮的等价形式：引入一个辅助变量 t 和一组非负松弛变量 z_s，对 S 个情景的损失 l_s = −r_s^T w，令

$$\text{CVaR}_\alpha = t + \frac{1}{(1-\alpha)S}\sum_{s=1}^{S} z_s, \qquad z_s \ge 0,\; z_s \ge l_s - t$$

当 t 取到 VaR_α 时，上式正好等于 CVaR_α，而 z_s 只在损失超过 t 的情景里取正值。于是「CVaR_α ≤ L」从一组**线性不等式**变成凸优化器手到擒来的东西。下面这段就是它的完整实现，没有黑盒：

```python
import cvxpy as cp
import numpy as np

# R: S×n 情景收益矩阵；alpha = 0.95
def min_cvar_portfolio(R, mu_daily, target_ret, alpha=0.95):
    S, n = R.shape
    w = cp.Variable(n)
    t = cp.Variable()
    z = cp.Variable(S)
    loss = -(R @ w)                       # 每个情景的组合损失
    cvar = t + (1.0 / ((1 - alpha) * S)) * cp.sum(z)
    cons = [cp.sum(w) == 1, w >= 0,
            z >= 0, z >= loss - t,
            mu_daily @ w >= target_ret]   # 至少要达到目标收益
    prob = cp.Problem(cp.Minimize(cvar), cons)
    prob.solve(solver=cp.CLARABEL)
    return w.value, float(t.value), float(cvar.value)
```

注意 `mu_daily @ w >= target_ret` 用的是「≥」而不是「=」：优化器在满足收益下限的前提下，会自己去挑那个尾部最薄的组合。这正符合「先保收益、再压尾巴」的实战逻辑。

这段目标函数对 (w, t, z) 全是线性的，约束也都是线性的，所以整个问题是**线性规划（LP）**而非二次规划。这带来两个实在的好处：一是求解快、数值稳，几千个情景也能秒级出解；二是没有局部最优，CLARABEL / OSQP / SCS 给出的都是全局最优。代价是 LP 对离群情景格外敏感——一个被错误放大的极端损失会被直接平均进 CVaR，这一点我们在结语再展开。

## 二、我们怎么造情景：埋一个崩盘因子

如果收益是纯高斯，那方差和 CVaR 几乎是一回事，文章就写不下去了。所以我故意造了一个**非对称的崩盘世界**：平时资产按各自的波动率做正态游走，但还有 2.5% 的概率会撞上一次系统性崩盘——所有资产齐刷刷地下跌，只是各自有一个不同的「崩盘 beta」。

```python
np.random.seed(20261028)
n = 8
mu_annual = np.array([0.062,0.078,0.055,0.091,0.103,0.047,0.118,0.041])
mu_d = mu_annual / 252.0
sigma_i = np.array([0.014,0.013,0.015,0.012,0.011,0.012,0.009,0.013])  # 日波动
beta = np.array([1.4,1.0,1.2,0.7,0.5,1.8,2.4,0.4])                      # 崩盘敏感度
nu = 4.0; sf = np.sqrt((nu-2)/nu)
z = sf * np.random.standard_t(nu, size=(6000, n))   # 厚尾残差
is_crash = np.random.rand(6000) < 0.025
crash = np.zeros(6000)
crash[is_crash] = np.abs(np.random.standard_t(4, size=is_crash.sum())) * 0.06
R = mu_d[None,:] + sigma_i[None,:]*z - beta[None,:]*crash[:,None]
```

关键设计：**科技**的日波动故意设得最低（0.009），崩盘 beta 却最高（2.4）。这模拟了一个常见陷阱——一个名字平时很「安静」、收益又高，方差优化会迷上它，但一旦崩盘它就变成最毒的那只。

## 三、结果一：CVaR 最优组合长什么样

把目标收益定在 9%，跑上面那段 CVXPY，得到的组合权重是：

| 资产 | 医药 | 消费 | 公用 | 其余 |
|---|---|---|---|---|
| 权重 | 53.4% | 31.7% | 14.8% | ≈0% |

也就是说，优化器自动把仓位全压在了崩盘 beta 最低的三个名字上（0.5 / 0.7 / 0.4），**完全没碰高收益的科技**——尽管科技收益最高。它的风险画像：

- 年化收益 **9.0%**，年化波动 **18.95%**
- VaR95 **18.97%**，CVaR95 **40.29%**

## 四、结果二：和朴素基准正面对比

光说自己好没意思，拉两个基准来比：

- **等权基准**：八只各 12.5%。年化收益只有 **7.44%**，CVaR95 却高达 **57.97%**——既没赚到、尾巴还更肥。
- **追高基准**：满仓收益最高的「科技」。年化收益 11.8% 看着诱人，但崩盘 beta 2.4 让它的最坏 5% 日子平均日亏年化口径高达 **119.37%**，组合随时可能被一次崩盘击穿。

![CVaR 有效前沿 vs 等权 / 满仓科技两个基准](/images/cvar-optimization-portfolio/fig2_frontiers.png)

把 CVaR 直接写进目标函数，得到的是 **9.0% 收益 + 40.29% CVaR**：相比等权，尾部风险下降约 30%（57.97% → 40.29%），收益反而更高；相比追高，它用少 2.8 个点的收益，换掉了超过一倍的尾部风险。这正说明了「管住最坏情况」不等于「少赚钱」。

值得一提：等权基准的 CVaR 比 CVaR 组合更高，收益却更低，说明它两头都不靠——既没做收益筛选，也没做尾部防护，只是机械地平摊。追高基准则是典型的「收益幻觉」：11.8% 的年化看着漂亮，但 119% 的 CVaR 意味着任何一次真实崩盘都会把它打回原形，经验上这种组合往往在创新高之前先被清盘。

## 五、结果三：成分 CVaR（Euler 分解）——重仓即尾险

知道组合整体 CVaR 还不够，实战里更需要回答：**这 40% 的尾巴，是谁贡献的？** 用 Euler 齐次分解，成分 CVaR 等于各资产权重乘上它在尾部的平均边际损失：

```python
def component_cvar(w, R, t, alpha=0.95):
    loss = -(R @ w)
    tail = loss > t                              # 落在尾部的情景
    cc = np.array([np.mean(-w[i] * R[tail, i]) for i in range(len(w))])
    return np.maximum(cc, 0) * np.sqrt(252.0)    # 年化
```

算出来三个持仓的成分 CVaR 分别是：

| 资产 | 医药 | 消费 | 公用 |
|---|---|---|---|
| 成分 CVaR（年化） | **23.93%** | 12.90% | 3.47% |
| 合计 | \multicolumn{3}{c}{40.29% = CVaR95 ✓} |

![成分 CVaR：尾部风险由哪些资产贡献](/images/cvar-optimization-portfolio/fig3_component_cvar.png)

一个反直觉但重要的点：**尾部贡献最大的，不是崩盘 beta 最高的科技（它压根没持仓），而是被重仓的医药**。成分 CVaR = 权重 × 尾部敏感度，所以哪怕一个资产本身很「安全」，只要它占了半仓，它就会变成组合最大的尾险来源。这对调仓的直接启示是：**降尾险不能只挑低 beta 名字，还得控制单一持仓的绝对权重**——Euler 分解就是把这条纪律量化出来的工具。在实盘里，它常被用作「风险预算」的分配依据：先定好每个资产能贡献多少尾险，再倒推仓位上限，比拍脑袋设「单票不超过 30%」要扎实得多。

## 六、结语与实操提醒

把 CVaR 写进目标函数，本质是逼优化器「对最坏情况负责」。在含崩盘因子的世界里，它自然演化出一套和方差优化不同的、更务实的持仓：躲开高崩盘 beta 的名字、控制重仓、用 Diversification 摊薄尾部。

几个落地时容易踩的坑：

1. **情景数量要够**。CVaR 是经验分布的分位数，S 太小（比如几百）时尾部估计噪声极大，最优权重会抖。本文用 6000 个情景。
2. **它是 LP，但对极端值敏感**。某个离群情景若损失特别大，会被平均进 CVaR，所以情景生成本身要可信—— garbage in, garbage out。
3. **CVaR 优化偏好厚尾资产的反面**。如果你的情景里某资产被设了不合理的巨 tail，优化器会过度回避它，权重塌到 0，反而丢掉收益。务必先核对情景的厚尾程度是否合理。
4. **别和方差优化混为一谈**。本文场景里崩盘是单一系统性因子，所以 min-CVaR 与 min-方差组合高度重合；一旦存在多个相互独立的厚尾源，两者会明显分叉——CVaR 组合通常愿意多扛一点日常波动，换取尾部更薄。到底用哪个，取决于你更怕「天天小亏」还是「十年一遇的大亏」。

完整代码就是上面三段的拼接：造情景 → `min_cvar_portfolio` 求最优权重 → `component_cvar` 做 Euler 分解。复制进一个 `.py` 文件，`pip install numpy cvxpy`，即可在你自己的收益矩阵上复现全部数字与三张图。
