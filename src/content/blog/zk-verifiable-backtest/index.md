做量化的人都知道一句话：**回测是免费的，可信的回测是昂贵的**。任何一篇策略文章、任何一份路演材料，都可以随手贴一条净值曲线，说自己年化 30%、夏普 1.5。但你——作为读者——凭什么信？你既看不到他的逐笔成交，也没法在一年前就盯着他跑完这段历史。传统的解法是「开源代码 + 公开数据」，但这条路有两个死穴：第一，真正赚钱的策略没人愿意开源；第二，就算开源了，你还得花和自己重跑一遍回测相当的成本去验证，而重跑又依赖你和他用同一份行情、同一套撮合规则。

**零知识可验证回测（Zero-Knowledge Verifiable Backtest）**想做的事很朴素：让研究者向全世界证明「我报出来的这份业绩，确实是由我私有的交易日志诚实算出来的」，同时**不泄露交易日志本身**。本文用三层构造把这件事落地，全部数值来自一段可复现的 numpy 模拟（256 个交易日的策略日志，总收益 30.49%、年化 29.95%、最大回撤 −11.35%、夏普 1.529），并给出从零实现的 Merkle 承诺、包含证明与 Pedersen+Schnorr 聚合和证明。

## 一、总览：三层信任栈

我们把「可信回测」拆成三个递增的需求：

1. **不可篡改**：日志一旦算完，研究者没法偷偷改几天的收益来美化曲线——这就是**承诺（commitment）**。
2. **可抽查**：第三方不用重跑全部 256 天，就能验证「第 137 天的收益确实写进了这份日志」——这就是**包含证明（inclusion proof）**。
3. **可聚合且零知识**：第三方能在不看到任何单日收益的前提下，确认「公开的总收益 = 日志里所有单日收益的合计」——这就是**零知识聚合证明**。

前两层用 Merkle 树（哈希）就能干净解决；第三层需要一点公钥密码学，但不需要任何第三方库——Python 的大整数原生支持 256 位模运算。

## 二、第一层：Merkle 承诺，给日志一个指纹

把每一天的收益（缩放到微元整数，避免浮点歧义）当作一个叶子，两两拼接做 SHA-256，自底向上递归，最终得到的根哈希就是整份日志的「指纹」。

![被承诺的策略净值曲线与回撤](/images/zk-verifiable-backtest/fig1_equity_curve.png)

```python
import hashlib

def sha(b):
    return hashlib.sha256(b).digest()

def merkle_root(leaves):
    """leaves: list[bytes]，返回 Merkle 根 bytes"""
    if len(leaves) == 1:
        return sha(leaves[0])
    if len(leaves) % 2 == 1:           # 奇数个叶子时复制最后一个
        leaves = leaves + [leaves[-1]]
    nxt = [sha(leaves[i] + leaves[i + 1]) for i in range(0, len(leaves), 2)]
    return merkle_root(nxt)

SCALE = 1_000_000
leaf_ints = [int(round(r * SCALE)) for r in daily_returns]   # 微元整数
leaves = [str(v).encode() for v in leaf_ints]
root = merkle_root(leaves)
print(root.hex())
# 180788533b15bda7c0f56e1619569018c20a6d3d541d994f5498b68618f9338d
```

承诺的核心性质是**抗碰撞**：你改了哪怕一天的一个微元，根哈希就会彻底变样。我们做了个雪崩实验——随机篡改 k 个叶子（k 从 1 到 128），看根哈希有多少比例的比特翻转：

![Merkle 防篡改雪崩效应](/images/zk-verifiable-backtest/fig2_merkle_avalanche.png)

结果非常「密码学」：无论篡改 1 天还是 128 天，根哈希平均都有约 **50%** 的比特发生变化（实测区间 49.4%–51.0%，理想雪崩正是 50%）。这意味着哪怕你只偷偷改了一天、而且改得「恰到好处」，外界也能以接近 1 的概率发现——因为根哈希对输入是雪崩敏感的。256 天日志的 Merkle 深度只有 **8**（log₂256），指纹长度恒为 32 字节。

## 三、第二层：包含证明，log₂N 次哈希抽查任意一天

Merkle 树的妙处在于，要证明「第 i 天的收益在日志里」，你不需要把 256 个叶子都发给验证者，只需要从叶子到根路径上的 8 个兄弟哈希（一个**包含证明**）。验证者把这 8 个哈希和待验证的叶子拼起来重算，得到的根若与公开根一致，就说明这一天确实被承诺过。

这是个巨大的审计成本优势。下面对比了「全量重跑」（成本 ~N）和「Merkle 包含证明」（成本 ~log₂N）随日志规模 N 的增长：

![审计成本缩放：对数级证明 vs 线性全量重跑](/images/zk-verifiable-backtest/fig3_audit_scaling.png)

当 N 从 16 涨到 65536，全量审计成本线性放大 4096 倍，而 Merkle 证明的成本只从 4 涨到 16——一条对数曲线和一条线性曲线在双对数坐标下彻底分叉。换句话说，验证者用 O(log N) 的代价，就能获得和「亲眼重跑一遍」同等的防篡改保证。

## 四、第三层：Pedersen + Schnorr，零知识证明总收益没造假

前两层解决「日志没被改」，但还没解决「**报出来的总收益等于日志真实合计**」。研究者完全可以在 Merkle 根之外，另报一个漂亮的总数。我们需要一个证明：**公开的总收益 T，确实等于私密日志里所有单日收益的求和**，而且证明过程不泄露任何单日收益。

用 **Pedersen 承诺**做到这一点。选一个大素数 p（这里用 NIST P-256 素数 2²⁵⁶−2²²⁴+2¹⁹²+2⁹⁶−1）和两个生成元 G、H。对第 i 天的收益 vᵢ，研究者选一个随机 nonce sᵢ，发布承诺 Cᵢ = G^{vᵢ}·H^{sᵢ} mod p。Pedersen 的两个关键性质：

- **同态**：所有承诺相乘，等于对「收益求和、nonce 求和」的一次承诺：∏Cᵢ = G^{Σvᵢ}·H^{Σsᵢ}。
- **绑定且隐藏**：给定 Cᵢ，你既不能把 vᵢ 改成别的数（绑定），也无法反推 vᵢ（隐藏）。

于是「Σvᵢ = T」这个陈述，等价于存在一个 S=Σsᵢ 使得 ∏Cᵢ = Gᵀ·H^S。研究者知道 S（因为 nonce 都是他选的），他用 **Schnorr 证明**向验证者证明「我知道 S，使得 Y = ∏Cᵢ·G^{−T} = H^S」——这就是一个标准的「 knowledge of discrete log」证明，天然具有**零知识性**：验证者除了确信陈述成立，学不到任何关于个别 vᵢ 或 sᵢ 的信息。

```python
P = 2**256 - 2**224 + 2**192 + 2**96 - 1   # NIST P-256 素数
G = 2
H = 123456789012345678901234567890123456789012345678901234567890123456789

def pedersen(v, s):
    return (pow(G, v, P) * pow(H, s, P)) % P

C = [pedersen(leaf_ints[i], nonces[i]) for i in range(N)]
prodC = 1
for c in C:
    prodC = (prodC * c) % P
T = sum(leaf_ints)                 # 公开声明的合计（微元）
S = sum(nonces) % (P - 1)          # nonce 合计，证明者私知

import hashlib
def fiat_shamir(a, Yv, Tv):        # Fiat–Shamir：把交互式挑战哈希化
    h = hashlib.sha256()
    h.update(a.to_bytes(64, "big")); h.update(Yv.to_bytes(64, "big")); h.update(Tv.to_bytes(64, "big"))
    return int.from_bytes(h.digest(), "big") % (P - 1)

def prove():
    k = py_random.randrange(0, P - 1)
    a = pow(H, k, P)
    c = fiat_shamir(a, Y, T)
    z = (k + c * S) % (P - 1)
    return a, c, z

def verify(a, c, z, Tv):
    Yv = (prodC * pow(G, -(Tv % (P - 1)), P)) % P
    return pow(H, z, P) == (a * pow(Yv, c, P)) % P
```

实测：诚实证明 `verify(a, c, z, T)` 返回 **True**；如果把公开总数篡改为 T+1 再验证，返回 **False**——因为此时 Y 不再是 H 的整数次幂（除非你能攻破 Pedersen 的绑定性，即求出 H 以 G 为底的离散对数）。整个证明只暴露三个大整数 (a, c, z)，单日收益始终留在研究者硬盘里。

## 五、zk 真正买到了什么，以及它的边界

把三层叠起来，我们其实得到了一个**可审计但保密**的回测发布协议：研究者在发布净值曲线的同时，附上 Merkle 根、一个聚合和证明，以及任意第三方想抽查的某几天的包含证明。读者不需要他的代码、不需要他的行情文件，就能独立确认「这条曲线背后的日志没被篡改，且报出来的总收益等于日志真实合计」。这对因子卖方、私募业绩展示、甚至链上策略托管都有直接价值——信任从「请你相信我」变成了「请你验证我」。

但三个边界必须说清楚，否则就是另一种形式的过度营销：

1. **GIGO 不可逾越**：zk 证明的是「数学上诚实」——日志里的数和公开总数自洽、未被篡改。它**证明不了日志本身是不是真的成交**。如果你喂给系统的「成交」是伪造的，证明依然会通过。密码学保证过程，不保证输入真理。
2. **预言机问题**：把真实市场数据接进承诺体系，需要一个可信的数据源（或另一套数据可用性证明）。否则「行情从哪来」成了新的信任黑洞。
3. **证明开销**：本文为了可读性在 256 天、Python 大整数上演示；真正把一年 252 个交易日、几百只标的的逐笔日志塞进 zk-SNARK，需要把求和改成多项式承诺（如 KZG）或更现代的 FRI/STARK，证明生成是实打实的计算成本。

## 六、结论

零知识可验证回测不是要把回测变成密码学杂技，而是给「自我报告型业绩」装上一个**可独立验证的封条**。Merkle 承诺用 32 字节给 256 天日志上锁，包含证明把抽查成本压到 log₂N，Pedersen+Schnorr 在不泄露单日收益的前提下锁死「总数 = 真实合计」。本文代码全部可运行（numpy 做模拟、纯 Python 大整数做证明），你把自己的 `daily_returns` 换进去，跑一遍就能拿到属于你自己的根哈希和证明。下一步的自然延伸，是把求和证明升级成 zk-SNARK 以支撑百万级日志——那才是它真正能进生产的地方。
