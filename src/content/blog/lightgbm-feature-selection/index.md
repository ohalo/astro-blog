因子工厂一旦开动，一天能吐出几百个候选因子：价量类的、基本面类的、另类的、还有各种变换组合。问题是——**绝大多数因子和未来的收益没有半点关系，只是历史数据里恰好长出的一朵噪声花**。如果一股脑把所有因子塞进模型，你不仅拖慢训练，还会给过拟合喂饱弹药。

所以因子筛选（feature selection）是量化流水线里绕不开的一环。本文用 LightGBM 在一份"已知真相"的合成数据上，演示如何**用树模型的重要性给几百个因子排座次**，并验证它真的能把信号和噪声分开。全文数字可复现，三张图均为真实计算产出。

更现实一点：因子越多，挖掘者无意中做过的"尝试"就越多。每一个被反复试验、挑出来"看起来有效"的因子，背后都藏着多次未报告的失败尝试，这就是多重检验（multiple testing）带来的伪发现（false discovery）。把候选集从几百压到十几个，本质上是在给后续的样本外检验留出更宽松的显著性空间——筛选不是目的，而是为了让留下来的因子经得起更严格的审视，而不是被淹没在成百上千次"恰好显著"的噪声里。

## 一、为什么用树模型排重要性，而不是看回归系数

线性模型也能给特征排重要性——看系数的绝对值大小。但它在因子筛选上有三个硬伤：

1. **吃不下非线性与交互**。真实的因子往往不是"线性叠加"，比如"低估值 + 高动量"才有效。线性模型要么漏掉，要么要靠人工堆交叉项。
2. **系数尺度不可比**。因子量纲不同（市盈率 vs 换手率），标准化后系数才可比，但很多因子本来就是非线性变换，标准化没意义。
3. **多重共线性会稀释系数**。两个高度相关的因子会互相"抢"系数，导致单个系数都变小，排名失真。

梯度提升树（这里用 LightGBM）天然规避这三点：它用**分裂增益（Gain）**衡量一个特征对减少损失的贡献，能自动捕获非线性与交互，且对特征的单调变换不敏感。LightGBM 提供三种重要性：

- **Gain**：该特征在所有分裂中带来的总损失下降，最推荐用于"谁更重要"。
- **Split**：该特征被选中分裂的总次数。
- **Weight**（覆盖数）：该特征影响的样本数。

## 二、造一份"真相已知"的因子面板

为了让结论无可辩驳，我们造一份合成数据：120 个候选因子，但**只有前 8 个含真信号**，其余 112 个纯噪声。目标是个股的"下期收益"。

```python
import numpy as np
import lightgbm as lgb
rng = np.random.default_rng(20261029)

n_stocks, n_periods, n_feat, n_true = 500, 60, 120, 8
n_obs = n_stocks * n_periods                       # 30000 条观测
period = np.repeat(np.arange(n_periods), n_stocks)
X = rng.standard_normal((n_obs, n_feat))

coefs = np.array([0.90, -0.70, 0.50, 0.40, -0.30, 0.25, 0.20, -0.15])
signal = X[:, :n_true] @ coefs
signal += 0.60 * np.tanh(X[:, 0] * X[:, 1])        # 非线性交互项（树可捕捉）
y = signal + rng.standard_normal(n_obs) * 0.80      # 加噪声

# 时间切分：前 70% 期训练，后 30% 期测试（避免前视）
tr = period < int(n_periods * 0.7)
X_tr, y_tr, X_te, y_te = X[tr], y[tr], X[~tr], y[~tr]
```

注意这里用了**按时间切分**而非随机切分——因子筛选如果随机打乱时间，测试集可能"偷看"到训练期的信息，给出过度乐观的结果。按时间先后切，才是诚实的样本外。

## 三、训练并看 Gain 重要性：信号浮上来了

LightGBM 对表格数据几乎不用调参就能跑得很好。我们固定随机种子，训练一个回归器：

```python
params = dict(objective="regression_l2", metric="l2",
              num_leaves=31, learning_rate=0.05, feature_fraction=0.9,
              min_child_samples=20, verbose=-1, seed=42)
booster = lgb.train(params, lgb.Dataset(X_tr, label=y_tr), num_boost_round=300)
gain = booster.feature_importance(importance_type="gain")
order = np.argsort(gain)[::-1]
```

全量 120 个因子的样本外 R² 是 **0.7460**。把 Gain 最高的前 20 个因子画出来（图 1，绿色是真因子、灰色是噪声），真相一目了然：

![图1 LightGBM 按 Gain 排序的前 20 个因子重要性](/images/lightgbm-feature-selection/fig1_importance.png)

前 8 名（F0–F7）正是我们埋进去的 8 个真因子，它们的 Gain 从 179444 一路降到 5917；而第 9 名开始掉进噪声区，Gain 只剩 400 上下——**比真因子低了整整 1–2 个数量级**。树模型几乎没有把分裂预算浪费在噪声上。

## 四、贪心选择曲线：达 95% 峰值只需 6 个因子

光看排名还不够。我们想知道："**如果只保留最重要的 K 个因子，样本外表现会怎样？**"做法很直接：按 Gain 顺序逐批加入因子，每加一个就重训一个只用这批因子的模型，记录样本外 R²。

```python
def oos_r2(model, Xs, ys):
    pred = model.predict(Xs)
    return 1.0 - np.mean((ys - pred) ** 2) / np.var(ys)

ks, r2_curve = range(1, n_feat + 1), []
for k in ks:
    cols = order[:k]
    m = lgb.train(params, lgb.Dataset(X_tr[:, cols], label=y_tr), num_boost_round=200)
    r2_curve.append(oos_r2(m, X_te[:, cols], y_te))
r2_curve = np.array(r2_curve)
```

曲线画在图 2。它从很低迅速爬升，在约 6 个因子处触及峰值 **0.7495**，之后长期平稳（略有极轻微的下探）。换句话说：**达到峰值 95% 的表现，只需要 6 个因子**；继续堆到第 8 个（全部真因子）R² 为 0.7484，和第 6 个几乎一样。

![图2 贪心加入因子时的样本外 R^2（筛选曲线）](/images/lightgbm-feature-selection/fig2_selection_curve.png)

一个值得玩味的细节：**全量 120 因子的 R²（0.7460）反而略低于只用前 8 个（0.7484）和峰值（0.7495）**。这说明那一堆噪声因子不仅没帮上忙，还因为引入了更多可拟合的参数，让模型在测试集上轻微退化。因子筛选在这里不只是"可解释性"的锦上添花，而是实打实地改善了样本外表现。

## 五、置换重要性：证明 Gain 不是过拟合假象

Gain 是在**训练集**上统计的分裂收益， skeptics 会问：它会不会只是模型在训练集上"记住"了某些噪声的巧合关联？最诚实的检验是**置换重要性（permutation importance）**：在测试集上，把某个特征的值随机打乱（破坏它和标签的关系），看模型误差涨多少。涨得多，说明这个特征真的在起作用。

```python
base_pred = booster.predict(X_te)
base_mse = np.mean((y_te - base_pred) ** 2)
for i in order[:15]:
    Xp = X_te.copy(); rng.shuffle(Xp[:, i])
    drop = (np.mean((y_te - booster.predict(Xp)) ** 2) - base_mse) / base_mse
    print(f"F{i}: {drop*100:.2f}%")
```

结果（图 3）和 Gain 排序**高度一致**：F0 打乱后测试 MSE 暴涨 270%，F1 165%，一路递减到 F7 的 6%；而第 9 名往后的噪声因子，置换后 MSE 变化在 ±0.1% 以内，等于"打乱也没影响"。两条独立的重要性度量互相印证，说明树模型的排序是**对分布本身的真实反映，而非训练集上的过拟合artifact**。

![图3 测试集置换重要性（Top-15）](/images/lightgbm-feature-selection/fig3_permutation.png)

## 六、落到实盘：怎么用重要性做筛选

把上面的流程接进你的因子流水线，建议这样用：

1. **先用 Gain 排个粗榜**，快速剔除 Gain 接近 0 的长尾因子（它们基本是噪声）。
2. **用选择曲线定 K**：找到 R²  plateau 的那个拐点，作为入模因子数。本例拐点约在第 6–8 个。
3. **用置换重要性做终审**：只用训练集 Gain 容易被共线性误导，置换重要性在测试集上给出更稳妥的判断。
4. **定期重算**：因子有效性会随时间漂移，重要性榜单也应随市场状态更新，别一次算完用三年。

还有一个实操细节：单一次函数调用得到的重要性本身也有随机性（树的随机抽样、特征抽样、行抽样都会引入方差）。稳妥的做法是在 K 折交叉验证里重复计算重要性，取均值并看标准差——如果某个因子在 5 折里有 3 折排进前 10、2 折掉到 50 名开外，那它的"重要性"并不可信，宁可当成边缘因子处理。本文为聚焦主线只跑了单次，实盘中务必加这一层稳健性检查，否则你会把噪声的偶然突出当成真信号。

## 七、必须知道的坑

- **相关因子会平分重要性**。如果两个因子高度相关（比如不同窗口的动量），Gain 会被它们"分掉"，单个排名都偏低，但合起来很重要。这时看"因子族"而非单个因子。
- **Gain 高 ≠ 因果、≠ 未来仍有效**。重要性只说明"在历史样本上对预测有用"，不保证逻辑成立，更不保证样本外持续。务必配合经济学解释和样本外验证。
- **类别不平衡 / 标签尺度**会影响 Gain 的绝对大小，跨实验比较重要性时要在同一设定下。
- **树模型对异常值敏感**，因子里的极端值会放大某些分裂的 Gain，清洗数据仍是前提。
