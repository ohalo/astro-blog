# 2026-10-31

## /stock 估值锚点重构：从「跟随股价」改为「价格无关」

### 发现的 bug（严重）
原 `defaultAssump` 把合理区间锚定在当日行情 PE/PB 上：
`peLow = peTTM*0.8, peHigh = peTTM*1.2` → 合理区间 = EPS × [0.8×PE, 1.2×PE] = **[0.8×股价, 1.2×股价]**。
两个后果：
1. 股价一动区间就跟着动 → 估值区间每天必变（用户反馈的现象）。
2. 现价必然落在 [0.8×P, 1.2×P] 内 → `bandOf` **永远返回 fair，永远不可能判出低估/高估**，功能空转。

### 修复方案
- `src/lib/valuation.ts` 新增：
  - `deriveFundamentals(price, peTTM, pb, shares)` → `{eps, bvps, roe, shares}`
    （eps = price/peTTM、bvps = price/pb，**价格与倍数同向变动 → 比值与价格无关**；
    roe = pb/peTTM 亦价格无关）
  - `justifiedPb / justifiedPe`：戈登增长/剩余收益 `PB=(ROE−g)/(COE−g)`、`PE=PB/ROE`
  - `deriveBands(fund, coe, g, growth)` → 三情景（悲观/中性/乐观）PE/PB 带，含锚定类型 kind
    （ROE 推导优先；ROE 不可用退回 PEG=1 锚点）
  - `fundamentalsEqual(a, b)` 容差 0.5% 比较，用于判定基本面是否真变了
- `StockQuote.astro`：存储换 key `sq_val_v2`，快照含 `{fund, zone, asOf, anchor}`；
  新增 `resolveValuation`（生成/加载假设 + 与快照 diff）、`briefHTML`（hero 摘要：
  锚定来源/EPS/BVPS/ROE/基准日）、`changeHTML`（变化说明：未变 vs 基本面更新警告）。

### 验证结论（bun 实测，固定 EPS=2/BVPS=10/ROE=20%）
- 股价 40→50，区间 `[19.19, 26.70, 34.21]` **完全不变** ✓（价格无关）
- 判定随价格正确翻转：@20→fair、@40/50→overvalued ✓（不再恒为 fair）
- 财报更新 EPS 2→2.4，区间整体上移 `[23.51, 33.07, 42.63]` ✓（有大事才变）

### 设计原则（后续改动需遵守）
估值区间的锚必须是**价格无关的基本面**（EPS/BVPS/ROE/股本），
绝不能由当日 PE/PB/股价反推，否则区间=股价±常数，判定永远为「合理」。
股价变化只改变「低估/合理/高估」判定，不改变区间本身。

## 操作经验
- 编辑大组件（StockQuote.astro，约 1600 行）时多步 Edit 可能中途丢盘/回滚，
  出现「调用点还在但定义没了」的损坏状态；发现后立即 `git checkout --` 回到干净基线重做，
  并**每步用 grep 计数校验**落盘，比一次性大改可靠。
